# LifeHub 工程审查

范围：现有 Android Java/Kotlin 应用、Room/SQLite 存储、本地账号、AI 后端、公开仓库可复现性。目标是适合作品展示的可靠本地应用，不是一次性改造成多租户云产品。

## 本轮落实

| 原问题 | 修复 | 验证方式 |
|---|---|---|
| AI 仅有占位云接口 | 默认本机 Ollama，严格 JSON schema，服务端二次校验 | 离线协议测试、真实模型评测 |
| 模型输入可误走付费服务 | 本机回环地址校验，拒绝重定向/系统代理，云适配器双开关，不自动回退 | 断言默认路径和禁用云路径 |
| 任务没有截止字段 | 添加日期、时区、唯一草稿 ID | 旧库迁移与并发确认测试 |
| 任务插入使用 REPLACE | 普通新增冲突中止，AI 新增独立事务 | 重复确认测试 |
| 账单升级破坏性清库 | 替换为显式迁移并导出 schema | v1/v2 兼容迁移测试 |
| 月份查询结束日期也包含在内 | 改为半开区间 | 边界 99/100/199/200 测试 |
| 日程升级删表 | 新增索引的非破坏性迁移 | 升级后旧行保留测试 |
| 账单写入未完成就提示成功 | 等待后台写入回调，失败留在表单；禁用重复保存按钮 | 账单界面保存测试 |
| 登录密码明文保存 | 随机盐 PBKDF2，后台线程执行，旧账号成功登录时原子迁移 | 单测及设备迁移测试 |
| 账号凭据和草稿默认参与备份 | 排除这两类 SharedPreferences 的云备份和设备迁移 | XML 配置审查 |
| 缺少可复现检查 | 后端测试、Android 单测、设备回归和界面测试、CI | 测试报告 |

## 仍需明确的边界

1. **本地账号隔离已完成。** 业务数据库、AI 草稿、财务分类按账号分开；升级时冻结旧数据归属，后台任务绑定原账号存储，旧会话页面被拦截。它仍不是服务端认证，不能宣传云端多租户安全。
2. **账单金额已迁移为整数分。** Finance v5 逐笔 HALF_UP 换算并保留旧值；后续仍需在导入新数据和新增币种时保持精度约束。
3. **日程仍有主线程 SQLite 操作。** 小规模演示可以工作，数据量大时可能卡顿。后续统一到 Room + Repository/ViewModel，先补功能测试再迁移。
4. **健康模块依赖 Android 使用情况权限。** 模拟器不能证明真实手机统计准确度，目前按系统前后台事件计算已记录时长，历史可能缺失，也不能据此提供医学健康结论。
5. **本地账号不是服务端认证。** 不支持云同步、远程会话、找回密码、跨设备同步，也不防有权限修改设备私有数据的人。本地数据库没有加密。
6. **开发后端只适合本机。** 公网部署需要认证、用户配额、TLS 网关和生产 HTTP 服务。不要把当前无认证开发端口直接暴露出去。
7. **小样本模型评测有限。** 固定用例用于回归和解释失败；不能把小规模样例准确率推广到所有输入。

## 下一阶段优先级

先补独立保留测试集与短演示视频，再处理日程线程模型。AI 取消等待和本地账号隔离现已实施；云部署仅在确有远程演示需求时再考虑。无需为简历提前租服务器或购买大模型套餐。

## 2026-09-30：前三项可靠性优化

- 已将开屏额外等待从 5000 ms 调整为 500 ms，按生命周期取消/恢复回调，保留 App 图标。
- 已补齐当前主要页面硬编码提示与 Finance 分类/账户显示翻译，修正删除账单提示乱码；用户输入和旧记录内容保持原样。
- Finance 和 Schedule 已增加数据库级草稿唯一键、事务确认与读回；重复提交不覆盖首次字段，返回原记录实际日期。
- 当时未实施项包括账户隔离、金额 double、日程主线程存储和头像 URI 持久性；其中金额和头像现已完成，见下方记录。

## 2026-09-30：Health 统计口径修复

逐日汇总已改为前后台事件区间按本地日期拆分，按完整包名区分应用；今日、七天图表与 Health 摘要统一计算，缺记录与缺权限明确区分。已删除默认两小时和跨日缓存回退。新增 8 项算法测试、3 项设备测试，实际 3.5 秒 Settings 会话记录增量 3523 ms。系统事件保留天数、漏报和多窗口归属仍有边界；完整说明见测试报告。

## 2026-09-30：后续四项改进

- 头像修复了写入 `user_prefs`、读取 `user_login` 的不一致，导入图片副本到私有目录；旧入口做兼容迁移。
- AI 模块确认不再提前消费 pendingAction，确认窗口、结果和已选模块支持重建恢复。
- Finance v5 整数分存储，统一小数位/上限校验；旧值与 ID 保留，迁移内核对笔数及总额，超限旧值回滚。
- 四模块评测从 8 条路由冒烟扩展为 40 条字段检查，真实本机 Qwen3 4B 的全部检查项通过率 70%。弱项包括分类留空、少量 Memo/Schedule 混淆和多任务被当作单项；本轮没有把这些模型失败伪装成通过，也没有宣称所有 AI 理解问题已经修复。
