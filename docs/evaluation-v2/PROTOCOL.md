# Bilingual holdout v2 protocol

The task is a new evaluation with 120 Chinese and 120 English inputs. There are 30 inputs per workflow per language. The 120 paired scenarios cover ordinary requests, absent fields, ambiguous and invalid dates/times, timezone boundaries, invalid monetary amounts, account ambiguity, vocabulary variation, cross-module wording, multiple independent commands and unsupported Health requests.

Case text, expected fields, date context, scoring rules and source hashes were frozen in `backend/evaluation/holdout_v2.lock.json` before any inference. No production changes or case corrections are allowed during this run. A detected benchmark ambiguity must be disclosed without silently changing its primary score. Original v1 and subsequent development results remain separate.

Each language has 98 expected supported drafts/navigation requests and 22 expected clarifications. The two languages use corresponding semantic scenarios, so they are correlated rather than 240 independent samples. They are not always literal translations. Most inputs share a fixed date context; timezone-boundary cases have intentionally different local dates. Exact old-prompt deduplication passed, but scenario-family overlap is not excluded.

One local model pass per input, fixed shuffled order, one excluded warmup, no retries. Retain raw output and errors. Routing is exact module plus status; required fields use the locked per-case list; all-field correctness also includes optional/date/time/title checks. Money compares exactly as finite Decimal values (formatting differences are accepted), while titles use bounded keyword checks. Other fields retain the existing exact/case-insensitive string policy. The money policy differs from v1 and prevents direct score comparison without qualification.

After inference, replay first-pass responses through the real Android review/navigation flow. Backend failures remain failed cases and do not become correct merely because a UI could open. Report workflow entry on supported requests and clarification outcomes separately. This is not per-case database insertion, comprehensive visual QA, mobile network timing or Health usage-measurement certification. Run the 13-case reliability suite separately for persistence, duplicate prevention, stale requests, account isolation and actionable clarification messages.

Latency is nearest-rank P50/P95, including backend validation and local model inference where invoked. Report all inputs and the subset which called the model. Do not start Gradle or automated emulator testing during inference; background OS/user workload is uncontrolled. One pass cannot establish variance or statistical significance. All inference uses the existing local Ollama/Qwen3 configuration, without paid cloud fallback.

This is an internally authored held-out set, not external independent validation. Once inspected, it becomes regression data for future work. Report Chinese and English counts and paired outcomes without claiming general language superiority.
